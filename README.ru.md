# steamfix

[English](README.md) | Русский

Делает клиент Steam на macOS «обычным» приложением с точки зрения системы:

- окна Steam получают стандартную форму окон macOS (системное скругление, рамка, тень);
- Stage Manager убирает окна Steam в полоску и возвращает их, как у любого приложения;
- в Dock остаётся одна плитка Steam — та же, с которой он запускается.

Файлы Steam не изменяются и не переподписываются. Всё работает через библиотеку, которая
подгружается в клиент при запуске, и фоновый агент, который следит, чтобы Steam запускался с ней.

## Требования

- macOS на Apple silicon или Intel; проверено на macOS 27.2 (26B123).
- Установленный и хотя бы раз запущенный Steam (`/Applications/Steam.app`).
- Xcode Command Line Tools (`xcode-select --install`): нужны `clang` и `swiftc`.

## Установка

```sh
make install
```

Затем закройте Steam, если он запущен, и откройте его как обычно. Проверка:

```sh
make status        # ничего не меняет, только показывает состояние
make stagetest     # переключает приложения на экране, проверяет Stage Manager
```

`make stagetest` нужно запускать из приложения, которое сейчас активно (например, из Терминала
на переднем плане), и при открытом окне Steam: macOS не даёт фоновому скрипту отбирать фокус, и
тогда проверка честно сообщает, что выполнить её не удалось.

Удаление — `make uninstall`, после него достаточно перезапустить Steam.

`make install` можно запускать повторно: он пересобирает всё и заменяет установленную копию,
сохраняя переключатели. При первой установке macOS покажет уведомление о новом фоновом
объекте `steamfix-agent`.

Что куда ставится:

| Путь | Что это |
| --- | --- |
| `~/Library/Application Support/SteamFix/Steam (fix).app` | лаунчер, библиотека, агент |
| `~/Library/LaunchAgents/local.steamfix.agent.plist` | автозапуск агента при входе |
| `~/Library/Logs/SteamFix-agent.log` | журнал агента (несколько строк на запуск Steam) |

## Почему это вообще нужно

Steam на macOS — два приложения. `steam_osx` владеет иконкой в Dock и строкой меню, но своих
окон не имеет. Все видимые окна принадлежат процессу `Steam Helper` — фоновому агенту
(`LSUIElement`), который рисует безрамочные окна через SDL. Для системы это «окна без рамки у
фонового процесса»: углы квадратные, а Stage Manager такими окнами не управляет.

## Как устроено

**Лаунчер** — [src/launcher.sh](src/launcher.sh). Запускает клиент
(`~/Library/Application Support/Steam/Steam.AppBundle/Steam/Contents/MacOS/steam_osx`) с
`DYLD_INSERT_LIBRARIES`, указывающим на библиотеку. Это возможно, потому что у клиента и у
`Steam Helper` нет hardened runtime.

**Библиотека** — [src/steamfix.m](src/steamfix.m). Ведёт себя по-разному в двух процессах:

- В `steam_osx`:
  - убирает `DYLD_INSERT_LIBRARIES` из окружения и возвращает её только при запуске
    браузерного процесса `Steam Helper`, так что игры и остальные дочерние процессы библиотеку
    не получают;
  - стартует как фоновое приложение и не даёт себе вернуться в Dock, пока жив `Steam Helper`;
  - отдаёт своё меню и принимает от `Steam Helper` команды (пункт меню, повторное открытие,
    выход, ссылка `steam://`) через `CFMessagePort` с именем `local.steamfix.<pid>`;
  - отбрасывает собственную реакцию «активировать себя, когда активен Helper» — иначе два
    обычных приложения бесконечно отбирают друг у друга фокус.
- В `Steam Helper` (только браузерный процесс, без `--type=`):
  - добавляет окнам SDL стиль `titled | closable | fullSizeContentView` и прячет системный
    заголовок: окно получает системную форму, а содержимое по-прежнему рисует Steam;
    всплывающие меню и Big Picture не трогаются (определяются по флагам `SDL_GetWindowFlags`);
  - делает процесс обычным приложением (`NSApplicationActivationPolicyRegular`) — этого
    достаточно, чтобы Stage Manager начал управлять окнами;
  - показывает в строке меню копию меню `steam_osx`; выбор пункта выполняется в `steam_osx`;
  - при регистрации в LaunchServices (`_LSApplicationCheckIn`) сообщает путь
    `/Applications/Steam.app` вместо своего. Dock сопоставляет плитки именно по этому пути,
    поэтому плитка получается одна. Внутри процесса при этом ничего не меняется.
  - так как система теперь считает его приложением Steam, клики по иконке, «Завершить» и
    ссылки `steam://` приходят ему; он пересылает их в `steam_osx`.

**Агент** — [src/agent.swift](src/agent.swift), LaunchAgent `local.steamfix.agent`. Steam,
запущенный обычной иконкой, из объектов входа или перезапустивший сам себя, стартует без
библиотеки. Агент замечает такой клиент в первую секунду, останавливает его и запускает
лаунчер. Он трогает только одиночный, только что запущенный клиент; повторные вызовы и уже
идущую сессию пропускает. Если после его перезапуска фикса всё равно нет, он отступает на
6 часов, а не зацикливается.

## Переключатели

Пустой файл с таким именем в
`~/Library/Application Support/SteamFix/Steam (fix).app/Contents/Resources`
(действует со следующего запуска Steam):

| Файл | Действие |
| --- | --- |
| `no-shape` | оставить окнам Steam их квадратную форму |
| `no-stage` | не делать `Steam Helper` обычным приложением (Stage Manager, меню и общая плитка выключаются) |
| `no-rename` | не регистрироваться как `/Applications/Steam.app` (у Steam будет вторая плитка) |
| `no-auto` | агент не вмешивается; фикс только при запуске через лаунчер |
| `debug` | писать журнал библиотеки в `~/Library/Logs/SteamFix.log` |

Запустить Steam с фиксом вручную, в обход агента:
`open "$HOME/Library/Application Support/SteamFix/Steam (fix).app"`.

## Проверено

| | |
| --- | --- |
| macOS | 27.2 (26B123), Apple M5 |
| Steam | клиент 1792618285, загрузчик 6.1 |
| Сборка | Apple clang 21.0.0, Swift 6.4.2 |

Проверялось: форма окон, уход окон в полоску Stage Manager и возврат, одна плитка в Dock при
обычном запуске, клик по иконке при работающем Steam, меню, ссылка `steam://open/downloads`,
выход через плитку, отсутствие библиотеки в дочерних процессах, отказ агента от зацикливания.

Не проверялось: запуск игр и оверлей, Big Picture, полноэкранный режим, автозапуск при входе
в систему, перезапуск Steam после его собственного обновления.

## Ограничения и риски

- Это вмешательство в работающий клиент. Библиотека опирается на внутреннее устройство Steam
  (имена классов SDL, порядок запуска процессов) и на недокументированную функцию
  LaunchServices. Обновление Steam или macOS может её сломать; тогда `make uninstall` или
  нужный переключатель возвращают штатное поведение.
- Valve не даёт гарантий для модифицированного клиента. В игры библиотека не передаётся, но
  исключить последствия для аккаунта нельзя.
- Если Steam не запущен, первая ссылка `steam://` может потеряться: агент перезапускает клиент,
  и адрес до нового экземпляра не доходит.
- Агент не трогает Steam, который работает дольше 20 секунд. Если при входе в систему Steam
  стартовал заметно раньше агента, эта сессия останется без фикса до перезапуска Steam.

## Что не сработало

Записано, чтобы не проходить заново.

- `LSUIElement = false` в `Info.plist` у `Steam Helper`: Steam возвращает файл при запуске;
  если файл заблокировать, ломаются обновления клиента, а два приложения начинают бесконечно
  отбирать друг у друга фокус.
- Флаги `collectionBehavior` у окон (в том числе `Primary`) на Stage Manager не влияют, пока
  владелец окна — фоновое приложение.
- Стиль окна без `closable`: CEF закрывает окно входа через `performClose:`, а без этого
  флага вызов игнорируется и пустое окно входа остаётся висеть за главным.
- Обёртка `Steam.app` вокруг `Steam Helper` (копия исполняемого файла, остальное ссылками)
  даёт правильную подпись плитки, но плиток становится две. `Info.plist` в такой копии менять
  нельзя: подпись Valve перестаёт сходиться и macOS убивает процесс при запуске (код 137).
- Переподпись копии ad-hoc запускается, но лишает процесс доступа к ключу «Steam Safe
  Storage» в связке ключей.
- Dock не объединяет плитки по идентификатору бандла — только по зарегистрированному пути.
  `_LSSetApplicationInformationItem` путь после регистрации не меняет.
- Переменная окружения `CFProcessPath` тоже даёт одну плитку, но подменяет главный бандл
  внутри процесса, от которого CEF ищет свои ресурсы.

## Отладка

```sh
touch "$HOME/Library/Application Support/SteamFix/Steam (fix).app/Contents/Resources/debug"
# перезапустить Steam, затем:
tail -f ~/Library/Logs/SteamFix.log
```

С включённым `debug` библиотека принимает команды (ответ пишется в тот же журнал):

```sh
make tools                        # собирает wins и sfcmd в build/tools
build/tools/sfcmd "helper:dump"   # политика активации, меню и окна Steam Helper
build/tools/sfcmd "main:dump"     # то же для steam_osx
```

Сбросить паузу агента после неудачной попытки:
`launchctl kickstart -k "gui/$(id -u)/local.steamfix.agent"`.

## Структура

```
src/steamfix.m       библиотека, подгружаемая в steam_osx и Steam Helper
src/agent.swift      фоновый агент
src/launcher.sh      исполняемый файл лаунчера
scripts/build.sh     сборка в build/
scripts/install.sh   сборка и установка для текущего пользователя
scripts/uninstall.sh удаление
tools/status.sh      проверка состояния (только чтение)
tools/stagetest.sh   проверка Stage Manager (переключает приложения)
tools/build.sh       сборка инструментов в build/tools
tools/lib.sh         общие функции для скриптов из tools/
tools/wins.swift     список окон Steam
tools/sfcmd.swift    отправка отладочных команд
```
